## 一、完成了什么

### 1. 任务数据模型（Room v3）
- `TaskEntity` 从 M1 的极简版扩展为完整流水线任务：每阶段独立的状态（`StageState`：PENDING/RUNNING/DONE/FAILED/NEEDS_INPUT）、进度、产物路径、错误信息、用户配置 JSON；任务级名称、源视频路径、创建/更新时间。
- 枚举存 `name()` 字符串，避免序数迁移问题；v2→v3 destructive migration（未发布可接受）。
- `TaskSnapshot.from()`：任务级状态推导（RUNNING/NEEDS_INPUT/DONE/FAILED）+ 总进度（四阶段均值）+ 当前阶段文案。
- `TaskFiles`：`filesDir/tasks/<id>/` 目录管理（transcript.json、translated.json、dub_track.wav、dub_meta.json、output.mp4、subs.srt）。

### 2. TaskRepository（持久化替换内存 Holder）
- CRUD + Flow 观察（`observeSnapshot`/`observeAllSnapshots`）；`setStageDone` 成功后自动把**下一阶段置 NEEDS_INPUT**（等用户在配置页确认）。
- M2/M3/M4 的内存 Holder（TranscriptionResultHolder 等）保留给前台独立流程；**任务流程的结果全部落盘**（JSON 文件 + Room），杀进程不丢。

### 3. WorkManager 长任务（4 个独立 Worker）
- `TranscribeWorker` / `TranslateWorker` / `DubWorker` / `SynthesizeWorker`，每阶段独立调度（**不硬链式**，因为阶段之间要用户介入）。
- inputData 只传 `taskId`，输入输出经 Room/TaskFiles（避开 WorkManager Data 体积限制）。
- `LongTaskWorker` 基类：final `doWork` 模板（参数校验→RUNNING→安全前台服务→`doStageWork`→成功/失败/取消）；进度双写 WorkManager Data + Room；前台通知 DATA_SYNC 类型显示阶段+百分比。
- `TaskScheduler`：按 `aivideo-task-<id>-<STAGE>` 唯一任务调度/取消；**失败重试 = 重调度失败阶段，已完成产物直接复用（断点续跑）**。
- 血泪教训落地：手写 `AiVideoWorkerFactory`（**不用 `@HiltWorker`**，Hilt 2.57.2+KSP 下绑定代码不生成）；manifest 用 `tools:node="merge"` 给 `SystemForegroundService` 声明 `foregroundServiceType="dataSync"`（合并后 manifest 已验证）；`tools:node="remove"` 去掉默认 WorkManagerInitializer；`AiVideoApp` 实现 `Configuration.Provider` 注入工厂。

### 4. NEEDS_INPUT 语义
- 翻译/配音/合成三个配置页支持任务模式（`?taskId=` 参数）：从任务目录读写、确认后把配置 JSON 落盘→阶段 PENDING→调度 Worker→返回任务详情。
- 任务详情页 NEEDS_INPUT 段显示"继续"按钮，路由到对应配置页；字幕编辑作为转写 DONE 后的次要动作（"校对字幕"，保存回任务目录）。
- 配音配置 `DubOptions` 从 ui 层移到 data 层（分层修正），避免 Worker 依赖 UI 包。

### 5. FFmpeg 合成导出（`SynthesizeUseCase` + `SynthesizeWorker`）
- **libass 核实结论**：`dev.ffmpegkit-maintained:ffmpeg-kit-full:8.1.7` 的构建脚本含 `--enable-libass`，AAR 内 libavfilter.so 静态链接了 libass（"Could not initialize libass renderer." 字串、`subtitles` 滤镜已注册）。**烧录滤镜可用**，无需降级。
- 字幕二选一：内嵌烧录（subtitles 滤镜）/ 外挂 srt（mov_text 字幕轨）。
- 编码预设二选一：原画质（`-c:v copy`，只处理音频；烧录模式被迫重编码时用 8000k 高码率近似）/ 压缩版（h264_mediacodec → libopenh264 → mpeg4 fallback 链，码率三档 1500k/3000k/6000k；音频统一 AAC 128k/44.1kHz/立体声）。
- 输出先写任务目录 `output.mp4`，完成后经 MediaStore 拷到 `Movies/AiVideo/`（按任务名）；支持分享（ACTION_SEND）/ 打开（FileProvider）。

### 6. 任务中心 UI
- 任务列表：状态徽标、总进度条、当前阶段文案；空状态精心设计（图标+引导文案）；删除二次确认。
- 任务详情：步骤条 下载→识别→翻译→配音→合成（导入即"下载"段已完成），每步等待/进行中/完成/失败/待确认一目了然；失败段显示原因+重试；NEEDS_INPUT 段"继续"按钮；合成完成后打开/分享成品。
- 首页新增"任务中心"入口；导入完成页新增"创建处理任务"按钮。

### 7. 开始前检查（`PreflightCheck`）
- 存储空间（估算 源视频×2+500MB，不足则**阻断**）、电量（<20% 且未充电则警告）、网络类型（移动数据+需要网络则警告二次确认）。
- 在"创建处理任务"入口弹窗：阻断只显示错误；警告列出后"仍要开始"/"取消"。

### 真机验证步骤（待用户）
1. 安装 APK → 首页"导入本地视频"选一个带音频的短视频 → 元信息页"创建处理任务"。
2. 检查弹窗：存储不足时应阻断（可用大文件模拟）；电量低/移动数据时应警告二次确认。
3. 跳转任务详情 → "开始识别" → 通知栏应出现"影译 · 识别"前台通知带百分比（需先在模型管理页下载转写模型）。
4. 识别完成后任务进"待确认" → "继续"进翻译配置页 → 确认 → 翻译 Worker 跑（需 LLM Key）→ 配音配置 → 配音 Worker（需 Kokoro 模型或云 TTS Key）→ 合成配置（选烧录/外挂、原画质/压缩）→ 合成 Worker。
5. 合成完成后：任务详情"打开"/"分享"；系统相册 `Movies/AiVideo/` 应有成品。
6. 杀进程重进：任务列表/详情进度应恢复（Room 持久化）。
7. 失败重试：任一阶段失败后点"重试"，应从失败阶段续跑（已完成阶段不重跑）。

## 三、已知问题

1. **端到端 FFmpeg 合成待真机验证**：沙箱 x86_64 跑不了 arm .so，`subtitles` 滤镜烧录、`h264_mediacodec` 硬件编码的真实执行效果需真机验证（命令拼装有单元测试覆盖，执行未覆盖）。
2. **后台启动前台服务限制**：API 31+ 应用在后台时 `setForeground` 可能被系统拒绝，已做 try-catch 降级（无通知继续执行，UI 仍可通过 Room 看进度），但极端情况下通知不显示。
3. **任务级取消语义简化**：取消后阶段回到 PENDING，无独立的 CANCELLED 状态；取消的 Worker 在 WorkManager 侧标记为失败重试计数（不影响 Room 状态）。
4. **翻译/配音的前台独立流程仍用内存 Holder**：M5 只把任务流程持久化了；前台"语音转写→翻译→配音"一条龙仍是内存传递（杀进程丢失），属历史行为，未改动。
5. **MediaStore 导出失败不算任务失败**：公共目录导出失败时任务仍标 DONE（私有目录产物可用，可分享/打开），UI 未提示导出失败——后续可加提示。
6. 构建期再次遇到 GRADLE_USER_HOME journal 锁冲突（父 agent 并行构建），等待对方结束后重试通过；**同一 GRADLE_USER_HOME 下避免多工程同时构建**（M1/M2/M4 同样出现过）。
