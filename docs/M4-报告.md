### 3. TTS data 层（`data/tts/`，全部新写）
- `TtsEngine` 接口：`synthesize(text, voiceId, speed)` → `SynthesizedSpeech(samples, sampleRate)`；端侧/云端同接口，配音流程只依赖接口
- `engine/OfflineKokoroTtsEngine`：Kokoro 封装。`init(modelDir)` 校验必需文件（含 espeak-ng-data 目录）；单段防御性截断 500 字符；sid 越界回退默认音色；`generate` 非线程安全由调用方串行
- `engine/OpenAiTtsEngine`：OpenAI 兼容 `/v1/audio/speech`（BYOK）。`buildSpeechRequest` 为纯函数（URL/鉴权头/JSON 体可单元测试）；返回 wav 落盘→`PcmDecoder` 解码 16kHz→线性重采样 24kHz 统一时间轴
- `TtsPreferences`（DataStore）：音色 sid/语速/引擎/策略/混音比例/仅 Wi-Fi/云音色名/云模型名/云 Base URL
- `TtsCredentialStore`：云 TTS Key 存 EncryptedSharedPreferences（独立文件 `tts_credentials`，与 LLM Key 分开字段；绝不硬编码）
- `DubAligner`（纯 Kotlin）：`plan(slotMs, audioMs)`——≤槽位补静音；≤1.2x 走 atempo 变速；超限截断+200ms 淡出并标记。`padSilence`/`truncateWithFade`/`msToSamples` 纯函数
- `DubTrackAssembler`（纯 Kotlin）：分段按字幕起始铺到 24kHz 时间轴，间隙静音，重叠后者覆盖；`assembleToWav` 输出标准 WAV
- `WavWriter`（纯 Kotlin）：16-bit PCM WAV 写/读回校验
- `AudioResample`（纯 Kotlin）：线性插值重采样（云 TTS 16kHz→24kHz）
- `DubSynthesizer`（编排）：逐段合成→对齐（变速段走 FFmpeg `buildChangeTempo`，解码回采样）→组装→混音模式走 `buildMixDubAudio`；全程 `ensureActive` 可取消；变速/混音失败抛带分段号的异常

### 对齐抽查报告（M4 交付物）
沙箱无法跑 arm 原生推理，用**合成时长模拟**跑了一遍对齐算法（`DubAlignerSimulationTest`，20 段；槽位 1.5~6s、源文按 4 字/秒反推、译文为源文 0.8~1.4 倍、Kokoro 中文约 4 字/秒±10%）：

```
=== DubAligner 对齐模拟抽查（20 段） ===
补静音：10 段（累计补 5399ms，平均 539ms/段）
变速对齐：6 段（最大 tempo=1.193，上限 1.2）
截断+淡出：4 段（分段号：4, 13, 14, 15）
结论：20 段对齐后时长均与槽位一致（误差 0ms）；截断段 4 段已全部标记待核对
```

解读：算法保证每段配音**起始与字幕槽位对齐、结束不超出槽位**，单段误差上确界为 0，满足技术方案"抽查 10 处误差 ≤ 1 秒"的验收口径；模拟显示译文膨胀是主要风险（4/20 段触发截断），实际使用中译文宜精简，截断段 UI 会标记"请核对"。

**用户真机验证步骤**：
1. 安装 `aivideo-debug-0.1.0.apk`
2. 首页「配音模型管理」→ 下载 Kokoro 模型（约 205MB，建议 Wi-Fi）→ 显示"已下载"
3. 任选链路产出翻译结果（转写链路或导入字幕文件翻译）→ 翻译结果页「下一步：配音」
4. 配音配置页：选一个中文音色（如 zf_001）→ 开始合成 → 观察逐段进度 → 试听页播放
5. 抽查：对比试听页分段徽标与字幕时间轴，配音应在各自槽位内、无串段；截断段检查译文是否被合理截断
6. （可选）云 TTS：首页「云 TTS 设置」→ 填自备 Key → 测试连接 → 配音配置页切到云端引擎合成对比

## 三、已知问题

1. **espeak-ng GPL-3.0 合规（产品级决策点）**：sherpa-onnx 原生库内编译了 espeak-ng 代码，Kokoro 全语言依赖其 phonemizer，"中英规避"不可行。严格解释下分发 APK 即构成 combined work。当前缓解：espeak-ng-data 不进 APK、assets 附 LICENSE、关于页声明（M6 落地）。长期三选一（开源/A进程隔离/换 phonemizer）需用户决策，详见许可证文档。
2. **端到端未验证**：真实 Kokoro 合成、对齐听感、FFmpeg atempo/amix 在真机上的实际表现待用户按上节步骤验证。`generate` 的实际耗时（整句一次性合成，长段可能数秒）也需真机摸。
3. **截断是信息丢失**：超 1.2x 的段会被截断+淡出。缓解：试听页标记"请核对"；后续可在配置页加"译文过长预警"（P1）。
4. **前台协程**：合成在前台协程串行执行，退后台可能被系统回收；M5 任务中心落地后改走 WorkManager。
5. **配音结果内存暂存**：`DubFlowHolder` 进程被杀丢失；M5 持久化到 Room。
6. **云 TTS 费用**：按服务商标准按量计费；测试连接会产生一小段费用，已在 UI 文案提示。
7. **Kokoro 长文本**：单段超 500 字符被防御性截断（Kokoro 对超长输入变慢/行为不稳定）；字幕分段通常远小于此值。
