## 一、完成了什么

1. **LLM 设置页**（`ui/settings/`）
   - OpenAI 兼容接口：Base URL、API Key、模型名；Key 存 EncryptedSharedPreferences（AES256，随卸载清除），已存 Key 显示掩码占位、不回显明文
   - 「测试连接」按钮：调 `GET /v1/models`，不发起真实翻译、不花钱；401/403/404/429/5xx 分别给中文原因
   - 隐私告知卡：密钥本机加密存储；只有用户主动发起的翻译请求会离开本机；第三方按量计费自理
   - 首页新增「LLM 设置」入口
2. **LLM 客户端**（`data/llm/LlmClient.kt`，独立实现）
   - `/v1/chat/completions` SSE 流式、可取消（协程取消即中断底层 Call）
   - 自研 SSE 行解析器（`SseParser`，纯 Kotlin）：data 行拼接、`[DONE]` 结束、注释心跳忽略
   - 超时/重试：连接 30s、读 180s（长翻译）、写 30s；网络 IO 异常退避重试 2 次；401 直接报 Key 无效不重试
3. **版本化 prompt 模板**（`app/src/main/assets/prompts/`，v1）
   - `system_prompt_v1.txt`：内置质量门禁——严禁编造/修改时间戳、严禁增减分段、严禁调换顺序、严格 `[序号] (开始-->结束) 译文` 格式、只输出译文行
   - `user_prompt_v1.txt` / `repair_prompt_v1.txt`：占位符模板；分段行时间格式与 `FormatUtils.formatTimestampMs` 一致
4. **翻译流程**（`data/llm/SubtitleTranslator.kt` + `ui/translate/`）
   - 字幕编辑页「下一步：翻译」已启用 → 翻译配置页（目标语言 7 预设+自定义、风格 直译/意译/口语化、术语表开关、双语开关；开始前检查 LLM 配置，缺失引导去设置页）
   - → 流式翻译进度页（阶段文案 + chunk 进度 + 已接收字符数，可取消）
   - → 翻译结果预览页（门禁未通过段显示「时间点待核实」徽标；SAF 导出 .srt；M4 配音入口占位）
5. **长文稿 map-reduce**（`TranslationChunker`，纯 Kotlin）
   - 保守 token 估算（CJK 0.8/字符、其他 0.35/字符）；超 12000 按 8000/chunk 切分；chunk 带全局连续序号与"第 X/Y 组"上下文
6. **时间戳质量门禁**（`TimestampGate` + `TranslationLineParser`，纯 Kotlin）
   - 校验：分段数一致、序号齐全、回显时间戳漂移 ±5 秒内、译文非空
   - 失败 → 一次 LLM 修正重试（repair 模板）→ 仍失败 → 保留最佳译文并标记 `verified=false`（不丢段，保证 SRT 连续性；UI 徽标提示手动核对）
7. **术语表**（Room `glossary` 表，DB v1→v2 destructive migration）
   - 增删改查 UI，按目标语言分组；翻译时注入 prompt + 输出后处理二次替换（`GlossaryPostProcessor`：长词优先、已含目标译法跳过）
8. **双语字幕选项**：原文+译文对照输出（预览与导出）
9. **纯字幕独立模式**（首页「翻译字幕文件」）
   - 自研解析器（`SubtitleParser`，无第三方依赖）：srt / vtt（含 WEBVTT 头、NOTE 注释、cue settings）/ ass（[Events] Dialogue 行，h:mm:ss.cc）
   - 解析 → 翻译配置页 → 结果页导出 .srt（SAF `CreateDocument("text/plain")`，文件名过滤非法字符）
   - 注：任务原文写 `CreateDocument("text/markdown")`，但 .srt 的正确 MIME 是 text/plain，已按后者实现

## 三、已知问题

1. **端到端未验证**：真实翻译需用户自备 Key，真机验证（步骤见上）。SSE 解析、门禁、修正重试链路目前只有单元测试覆盖。
2. **模型幻觉风险**：门禁能抓到数量/时间戳违规，但抓不到"译文驴唇不对马嘴"；质量依赖所选模型，temperature 已设为 0.3 降低随机性。
3. **超长视频费用**：流式翻译按 token 计费；chunk 较多时建议先用小模型试一小段。后续可在配置页加 token 预估（P1）。
4. **翻译结果内存暂存**：`TranslationFlowHolder` 进程被杀丢失；M5 任务中心落地后持久化到 Room。
5. **术语表后处理是纯字符串替换**：极端情况下可能误伤（如术语恰好是常用词）；长词优先+已含目标译法跳过已降低概率。
6. **模型直链/接口兼容性**：各家 OpenAI 兼容接口的 SSE 实现细节略有差异；如遇某家解析异常，诊断时先看 logcat 的 HTTP code。
