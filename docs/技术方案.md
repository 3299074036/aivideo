# 技术方案：「AI 视频处理」Android App（项目名待定）

> 状态：**M1~M6 已完成（2026-10-17），构建验证通过**；端到端真机验证待用户进行。
> 日期：2026-10-17（M6 更新）
> 版本：0.1.0（versionCode 1）
> 参考创意：VideoPrinterTurbo / MoneyPrinterTurbo（桌面端 Python 项目）的任务流水线思想——下载 → ASR → 翻译 → 配音 → 合成。本方案为独立 Android App 实现，不复用其代码。

## 0. 前置核实（与原提示词的出入）

1. **仓库地址**：`leftatrium2/VideoPrinterTurbo` 经核实不存在（该账号下只有 `convert_youtube_ttml_to_srt` 等小项目）。与描述相符的开源项目是 `harry0703/MoneyPrinterTurbo`（MIT 协议，曾用名 VideoPrinterTurbo），功能是"一句话生成短视频"。本 App 借鉴的是它的"可视化任务流水线"思想，而非代码复用。
2. **yt-dlp 许可证纠偏**：原提示词写"注意其 GPL 协议影响"——经核实，**yt-dlp 是 Unlicense（公有领域式），不是 GPL**，打包进 App 不产生传染性义务。真正的合规风险不在许可证，而在平台服务条款（见 §7）。
3. **与「视记」的关系**：本机已验证 sherpa-onnx ASR 链路可行（视记 M3），设计参数（模型选型、分块策略、下载源）可供参考，但 **aivideo 独立实现，不复制视记代码**，保持工程独立干净。

## 1. 总体架构

- **语言/UI**：Kotlin + Jetpack Compose + Material 3 Expressive，Material You 动态取色，深色模式完整适配；全 App 同一套 Design Token（圆角/间距/字阶）。
- **架构**：MVVM + Clean Architecture（data / domain / ui 分层），Hilt 依赖注入。
- **本地存储**：Room（任务、字幕分段、术语表、配置）+ DataStore（设置项）；密钥进 EncryptedSharedPreferences。
- **后台任务**：WorkManager 链式任务 + 前台服务（DATA_SYNC 类型），阶段状态机驱动；杀进程后 WorkManager 自动恢复。
- **网络**：OkHttp + Retrofit；支持 HTTP/SOCKS5 代理（OkHttp 原生支持）。
- **目标**：minSdk 26，arm64-v8a only（x86_64 仅模拟器调试），targetSdk 35。

## 2. 模块详细设计

### 2.1 视频导入与下载

- **本地导入**：SAF / 相册选择；展示元信息（MediaMetadataRetriever：分辨率、时长、大小、音轨/内嵌字幕）。
- **链接下载**：yt-dlp 独立进程调用（不与主进程同 JVM）。参考 YTDLnis 做法：App 内置 Python 3.x 运行时，**yt-dlp 做成独立更新通道**（extractor 随站点改版频繁失效，必须可热更新而不发版）。
- **P1 批量下载**：URL 队列（上限 100），顺序执行，单个失败不阻塞队列。
- **不做**：付费墙/DRM/登录态绕过、反爬对抗。仅处理公开可访问内容。

### 2.2 语音识别（三档）

1. **端侧默认**：sherpa-onnx（独立实现），whisper tiny-int8 默认，SenseVoice / small-int8 可选；输出词级时间戳 → 分句（30 秒上限）。
2. **远程自建 Whisper**：用户填地址，OpenAI 兼容 `/v1/audio/transcriptions`。
3. **云端 ASR**：用户自备 Key，费用处明确提示。
- 识别结果可预览、编辑、手动校准时间轴（字幕编辑器为 M2 交付）。

### 2.3 字幕翻译与改写

- BYOK：OpenAI 兼容接口，SSE 流式生成、可取消；`assets/prompts/` 版本化 prompt 模板。
- 目标语言选择、翻译风格（直译/意译/口语化）、术语表（自定义词汇对照，prompt 注入 + 后处理替换）。
- 双语字幕选项（原文+译文对照）。
- 独立模式：导入 srt/vtt/ass → 输出翻译后字幕（自研解析器，不引入重型库）。
- 长文稿 map-reduce（12000 token 上限，超限切 8000 token/chunk 再合并），时间戳质量门禁（±5 秒校验→一次 LLM 修正重试→失败剔除并标注「时间点待核实」）——aivideo 独立实现。

### 2.4 AI 重新配音

- **端侧优先**：Sherpa-ONNX + Kokoro-82M（Apache-2.0），多音色可选、语速可调。
- **云 TTS 备选**：用户自备 Key。
- **配音策略**：替换原音轨 / 与原音混音（可调比例）；按字幕时间轴自动对齐；超长句子用 FFmpeg `atempo` 变速适配（0.8~1.2 安全区），超出则截断+淡出并标注。
- **许可证注意（2026-10-17 M4 已实测更正）**：sherpa-onnx AAR 的 `libsherpa-onnx-c-api.so` 内**编译了 espeak-ng 代码**（GPL-3.0，strings 实测命中；Kokoro 全语言含英文都经 espeak-ng phonemizer，`espeak-ng-data/` 不可绕开）。原"首版中英规避"设想**不可行**，特此更正——该 AAR 自 M2 起就在包里。严格解释下随 APK 分发即构成 combined work。**用户已决策（2026-10-17）：接受 GPL-3.0（含源码开放义务）**，备选 B/C 不再推进。落地清单见许可证文档（LICENSE 文本 + 关于页声明 + 分发时提供源码获取方式，M6 落地）。

### 2.5 合成与导出（FFmpeg，选型结论见 §4.1）

- 字幕：内嵌烧录（`subtitles` 滤镜）/ 外挂 srt（二选一）。
- 编码预设：原画质（copy 视频流，仅处理音频）/ 压缩版（H.264 + AAC，码率档位可选）。注意 LGPL build 无 x264，用 FFmpeg 内置 `mpeg4`/`libopenh264`（如可用）或 MediaCodec 硬件编码（`h264_mediacodec`）。
- 输出管理：App 私有目录 → 用户确认后移至公共目录（MediaStore），按任务命名，支持分享/打开。

### 2.6 素材替换（P1，M6 已实现）

- Pexels/Pixabay 官方 API 按关键词搜免费素材（Key 用户自填 BYOK，
  EncryptedSharedPreferences 加密存储），替换原视频片段（画面替换、音频保留
  原音轨；素材自动 scale+crop 到源分辨率）。
- 授权信息（提供方、片段 id、作者、授权页、许可证名、落盘文件名、被替换片段
  起止）随任务存档：`tasks/<id>/licenses.json`（任务删除时一并清除）。
- 替换产物为 `tasks/<id>/replaced.mp4`，合成配置页可选用它作为合成源
 （`SynthesizeOptions.useReplacedVideo`）。

### 2.7 任务中心

- 任务列表：排队中/下载中/识别中/翻译中/配音中/合成中/完成/失败；细粒度进度（百分比 + 阶段文案 + 预估剩余）。
- 每步产物落盘（Room 记录路径），失败可从失败步骤续跑；失败任务保留中间产物。
- 任务开始前检查：剩余存储、電量、网络类型（移动数据二次确认）。

### 2.8 设置（M6 已实现统一设置页）

- 统一设置页分组：模型与服务（语音/配音模型管理、LLM 设置、云 TTS 设置、术语表）、
  素材与下载（素材库设置、yt-dlp 链接下载）、应用（关于与开源许可）。
- 密钥类配置全部 BYOK + EncryptedSharedPreferences 加密存储；关于页含 GPL-3.0
  声明与第三方组件清单（`ui/settings/ThirdPartyLicenses.kt`，与许可证文档同步维护）。
- 未实现（延后）：代理（HTTP/SOCKS5）、主题/语言切换、诊断日志导出。

## 3. 流水线 UI（视觉核心）

- 任务详情页步骤条：下载→识别→翻译→配音→合成，每步状态（等待/进行中/完成/失败/跳过）一目了然。
- 耗时操作一律细粒度进度，禁止白屏干等；空状态/错误状态精心设计（原因 + 重试按钮），不抛原生 Toast 了事。

## 4. 关键技术选型与许可证合规结论（M1 前必须定案）

### 4.1 FFmpeg —— 结论：用社区维护分支的 LGPL 构建

经核实：

- 原 `arthenica/ffmpeg-kit` 已于 **2025 年 4 月归档停止维护**。
- 社区维护分支 **`ffmpegkit-maintained/ffmpeg`**（Android-only）：API/包名与原版相同，**LGPL-3.0**，支持 targetSdk 35 与 **16KB 内存页**（Google Play 2025 年 11 月起强制要求，否则新设备 SIGBUS 崩溃）。
- **选型：`ffmpegkit-maintained/ffmpeg` 的 LGPL build（不含 x264/x265/libvidstab 等 GPL 编码器）**。
- 合规做法：AAR 动态链接（已满足 LGPL 动态链接要求）+ App 内「开源许可」页署名 + 提供 FFmpeg 源码获取方式说明。App 本体可保持闭源。
- **禁止**：Full-GPL build（含 x264），否则整个 App 必须 GPL-3.0 开源。

备选：Media3 Transformer（纯原生、无许可证负担），但字幕烧录/atempo/混音等复杂滤镜仍需 FFmpeg。首版以 FFmpeg 为主。

### 4.2 视频下载 —— 结论：yt-dlp（Unlicense），不推荐 NewPipeExtractor

| 方案 | 许可证 | 结论 |
|---|---|---|
| yt-dlp（Python 独立进程 + 独立更新通道） | **Unlicense**（非 GPL，无传染） | ✅ 推荐。参考 YTDLnis：内置 Python 3.x，yt-dlp 可独立热更新 |
| NewPipeExtractor | GPL-3.0 | ⚠️ 会传染整个 App，**不推荐**（除非 App 决定整体开源） |
| 各平台公开 API / 直链解析 | — | 降级备用 |

体积影响：Python 运行时约 +30~50MB；FFmpeg 约 +20MB/ABI。首版 APK 预计 80~120MB，arm64-v8a only。

### 4.3 端侧 AI —— 结论：sherpa-onnx 统一承载 ASR+TTS

| 组件 | 许可证 | 结论 |
|---|---|---|
| sherpa-onnx | Apache-2.0 | ✅ 可商用，Android 有官方 AAR |
| whisper.cpp | MIT | ✅ 可商用（本方案经 sherpa-onnx 间接使用 whisper 模型） |
| whisper 模型（tiny/base/small） | MIT（OpenAI 权重） | ✅ 按需下载，不打包 |
| Kokoro-82M | Apache-2.0 | ✅ 模型可商用；但 sherpa-onnx AAR 内含 espeak-ng（GPL-3.0）代码且 Kokoro 必经其 phonemizer，"中英规避"不可行，见 M4 报告 |
| ONNX Runtime | MIT | ✅ |
| yt-dlp | Unlicense | ✅ |
| 自研 srt/vtt/ass 解析 | — | 无第三方依赖 |

## 5. 数据流与状态机

```
导入 → 下载 → ASR → 翻译 → 配音 → 合成 → 完成
         ↓       ↓       ↓        ↓        ↓
       产物落盘（Room 记录路径+哈希），任一步失败可从该步续跑
```

- WorkManager 链式 OneTimeWorkRequest，每步独立 Worker，输入输出经 Room 传递（避免 Data 体积限制）。
- 前台服务通知显示当前阶段 + 百分比；支持暂停（取消当前链）、取消、重试失败步骤。

## 6. 风险点

1. **FFmpeg 社区分支持续性**：非官方维护，若停更则预案为按公开 LGPL 16KB patch 自行 NDK 编译（有现成 patch 参考）。
2. **yt-dlp extractor 失效频率**：站点改版是常态，必须做独立热更新通道；失败时给明确文案（"站点解析失效，尝试更新解析器"）而非未知错误。
3. **包体积**：80~120MB 首版，需在产品页管理预期；模型全部按需下载不打包。
4. **端侧性能**：whisper tiny-int8 在中端机 5 分钟音频约 1~3 分钟；Kokoro 合成实时率约 5~10x；大视频分段处理防 OOM。
5. **配音对齐精度**：TTS 时长与字幕槽位天然不匹配，atempo 安全区 0.8~1.2，超出需截断+标注；"10 处抽查 ≤1s"可达，但需真机实测调参。
6. **后台存活**：国内厂商 ROM 杀后台激进，除前台服务外需引导电池优化白名单。
7. **Play 政策**："视频下载"功能敏感。建议上架版弱化下载表述（"导入公开链接"）+ 强化版权提示；或首版先走 GitHub/F-Droid。
8. **espeak-ng GPL（M4 已实测，用户已决策接受 GPL-3.0）**：AAR 内含 espeak-ng GPL-3.0 代码且不可绕开，"中英规避"不成立；用户 2026-10-17 决策接受 GPL-3.0（含源码开放义务）。M5/M6 按现状继续，合规落地清单（LICENSE 文本、关于页声明、源码获取方式）M6 做。

## 7. 合规要求落地

- 首启 + 下载页显著位置版权提示：仅处理拥有权利或已获授权的视频；下载他人视频可能违反平台条款与著作权法，后果自负。
- 不做付费墙/DRM/登录态绕过、反爬对抗；yt-dlp 仅用于公开可访问内容。
- Pexels/Pixabay Key 用户自填，授权信息随任务存档。
- 开源许可页列出全部第三方组件及许可证；LGPL 源码获取说明。

## 8. 里程碑（M1~M6）

- **M1**：工程脚手架 + 本方案确认 + FFmpeg 集成验证（跑通一次转码）+ 视频导入（本地导入先行，链接下载随后）。输出：可构建工程 + 转码验证报告。
- **M2**：模型管理 + 端侧 ASR + 字幕预览/编辑（独立实现）。输出：转写 demo。
- **M3**：LLM 翻译/改写 + 术语表 + 双语字幕 + 纯字幕翻译独立模式。输出：翻译 demo。
- **M4**：端侧 TTS + 时间轴对齐。输出：配音 demo + 对齐抽查报告。
- **M5**：FFmpeg 合成导出 + 任务中心（状态机、断点续跑）。输出：合成 demo。
- **M6**：素材替换（P1）、批量下载（P1）、设置页、端到端联调。输出：5 分钟公开视频全流程 demo。
  ——**已完成（2026-10-17）**：素材检索/替换/授权存档、yt-dlp 批量下载与独立更新通道、
  统一设置页 + 关于页（开源许可清单）、GPL 合规落地（工程根 LICENSE、
  关于页声明、源码分发清单）、集成测试补齐。详见 `M6-报告.md`。

每个里程碑结束输出：完成了什么、如何验证、已知问题。
