# M2 报告：模型管理 + 端侧 ASR + 字幕预览/编辑

> 日期：2026-10-17　状态：**完成**（构建通过、单元测试 35/35 全过）
>
> 特别说明：本里程碑**独立实现**，未复制视记任何源码。用户明确要求后，
> 此前误建的 17 个移植文件已走回收站清理；所有 Kotlin 代码均为 aivideo 新写。
> sherpa-onnx 的 Java API 以 AAR 内 classes.jar 经 javap 核实为准；
> whisper 空 language 触发自动语种检测的结论来自上游
> `offline-whisper-greedy-search-decoder.cc` 源码（`if (!config_.language.empty()) … else DetectLanguage(…)`）。

## 一、完成了什么

1. **语音模型管理页**（`ui/models/`）
   - 三档：Whisper Tiny int8（默认）/ SenseVoice int8 / Whisper Small int8，radio 切换（仅已下载可选）
   - 体积展示、下载/暂停/断点续传/删除、进度条（已下载/总量）、失败重试
   - 「仅 Wi-Fi 下载」开关（默认开，DataStore 持久化）
   - 模型存 `filesDir/models/<modelId>/`，随应用卸载清除
   - 底部**FFmpeg 版本诊断行**（M1 报告承诺）：调用 `FFmpegService.getVersion()`
   - 首页新增「语音模型管理」入口按钮
2. **模型下载器**（`data/asr/ModelDownloadManager.kt`，独立实现）
   - OkHttp + HTTP Range 断点续传：`.part` 临时文件，206 续传 / 200 从头；
     暂停保留已下载部分，杀进程后可续传；多文件跨文件聚合进度
   - 模型地址：sherpa-onnx 官方维护者（csukuangfj）的 HuggingFace 仓库直链，
     2026-10-17 逐个 `curl -I` 验证可达（见 `AsrModelCatalog`）
3. **端侧 ASR 链路**（`data/asr/`，独立实现）
   - `PcmDecoder`：MediaExtractor + MediaCodec 解码音频轨 → 流式混音/线性重采样到
     16kHz 单声道 → 直接写 PCM 文件（**不经过内存大数组**，1 小时视频也不 OOM）
   - `ChunkResampler`：流式重采样器，块边界无缝（与一次性重采样逐采样点一致，
     已用 Python + 单元测试双重验证；实现中曾发现边界钳制 bug 并修复）
   - `SherpaAsrEngine`：sherpa-onnx 1.13.8 封装；whisper（tiny/small）走
     encoder/decoder + tokens，`language=""` 触发自动语种检测，`enableTokenTimestamps=true`
     取词级时间戳；SenseVoice 走 `model.int8.onnx` + `language="auto"` + ITN；
     按 60 秒块流式转写（`transcribePcmFile` 从 PCM 文件切片读取）
   - `SentenceSegmenter`：纯 Kotlin 分句——中英文标点分句、单句 30 秒上限强制断句、
     西文词间补空格；SenseVoice 无词级时间戳时按标点分句、按字数比例分配时长兜底
   - `TranscribeAudioUseCase`：编排（解码 15% → 分块转写 75% → 分句），阶段回调，
     协程取消即停，临时 PCM 文件善后清理
4. **转写页**（`ui/transcribe/`）：检查模型 → 未下载引导模型页 → 二次确认
   （前台运行提醒：保持本页在前台）→ 阶段式进度（解码中/识别中 x/y 段/分句中）→
   成功进字幕编辑页；失败原因 + 重试
5. **字幕预览/编辑页**（`ui/subtitles/`）：分段列表、文本直接编辑、点时间行弹
   校准对话框（秒，支持小数）、删除分段；底部「下一步：翻译」为 M3 占位（禁用注明）
6. **导航**：新增 `MODEL_MANAGEMENT` / `TRANSCRIBE?filePath=` / `SUBTITLE_EDIT` 路由；
   导入元信息页加「语音转写」按钮（无音频轨时禁用）；转写结果经
   `TranscriptionResultHolder` 内存传递（M5 持久化到 Room）
7. **配套**：`app/build.gradle.kts` 引入 sherpa-onnx AAR（`files(...)`，
   未引入 onnxruntime-android）；`AsrModule`（Hilt）；`FormatUtils.formatTimestampMs`；
   第三方组件许可证文档补 sherpa-onnx 与三档模型来源/许可证

## 三、已知问题

1. **端到端未验证**：解码 + sherpa 推理需真机；`SherpaAsrEngine.init` 的参数
   （`tailPaddings=1000` 等）按上游常见配置设定，真机若初始化失败，日志会给出缺失文件明细。
2. **SenseVoice 时间戳为近似值**：该模型不输出词级时间戳，分句时长按字数比例分配；
   验收标准"抽查 10 处 ≤1s"建议用 whisper 档验证。
3. **转写跑在前台协程**：退后台可能被系统回收（二次确认已提醒）；WorkManager 统一是 M5 的事。
4. **转写结果内存暂存**：进程被杀丢失；M5 任务中心落地后持久化到 Room。
5. **模型直链时效性**：HF 仓库更新后旧直链可能 404；地址集中在 `AsrModelCatalog`，一处修改即可，
   后续可加"检查更新"（P1）。
6. **构建期 journal 锁冲突**：与并行的 videonotes 构建抢 `GRADLE_USER_HOME` 锁失败两次、
   daemon 被杀一次；均为外部干扰，重试即过。建议同一 GRADLE_USER_HOME 下避免多工程同时构建。
7. **APK 体积 88.7MB**：sherpa-onnx 四架构 .so（打包时仅取 arm64-v8a，体积主要来自 onnxruntime），
   模型按需下载不计入。
