## 一、完成了什么

### 1. 素材替换 P1（`data/stock/` + `ui/stock/`）

- **素材检索**：Pexels / Pixabay 官方 API（`StockClient`，OkHttp + Gson，
  无新增第三方库）。Key 用户自填 BYOK（`StockCredentialStore`，
  EncryptedSharedPreferences，与 LLM/云 TTS 的 Key 分开存放）。
  搜索统一映射为 `StockClip`（选 mp4、≤1080p 的最大分辨率文件）。
- **素材库设置页**：默认提供方选择、双 Key 管理（不回显明文、非空覆盖保存）、
  「测试连接」（真实搜索 1 条验证 Key 有效）+ Key 申请与授权说明卡。
- **任务内流程**：任务详情页「素材库：替换视频片段」→ 搜索/下载
  （落盘 `tasks/<id>/stock/` + 元信息 sidecar JSON）→ 输入起止秒数 →
  FFmpeg 三段 concat 替换（`FFmpegCommandBuilder.buildReplaceSegment`，纯 Kotlin
  可测试）→ 产物 `tasks/<id>/replaced.mp4`。
- **授权存档**：每次下载/替换成功后追加 `tasks/<id>/licenses.json`
  （提供方、片段 id、作者、授权页、许可证名、落盘文件名、被替换片段起止），
  任务删除时一并清除。
- **合成联动**：`SynthesizeOptions.useReplacedVideo`（Gson 缺字段回退默认，
  老配置 JSON 兼容）；合成配置页在 replaced.mp4 存在时展示开关；
  `SynthesizeWorker.resolveVideoSource`（纯函数）：选用且文件存在才用替换版，
  否则回落源视频（替换产物被删不阻断合成）。
- 说明：只替换画面，音频保留源视频完整音轨；素材自动 scale+crop 到源分辨率。

### 2. 批量下载 P1（yt-dlp，`data/ytdlp/` + `ui/ytdlp/`）

**集成方式（先调研后确定，详见 `yt-dlp集成调研.md`）**：
- 官方无 Android 可用原生二进制（`yt-dlp_linux_aarch64` 为 glibc 构建，
  bionic 跑不了）；业界验证路线（Seal / youtubedl-android）=
  **bionic 版 CPython 解释器随 APK 内置** + **官方 `yt-dlp` zipimport 纯 Python
  归档（约 2.9MB）运行时按需下载** + ProcessBuilder 调用
- API 29+ 不允许从可写私有目录执行 ELF → 解释器必须走
  `jniLibs → nativeLibraryDir`（`libpyinterpreter.so`），不能运行时下载；
  yt-dlp 归档是传给解释器的脚本参数，可放 filesDir
- `youtubedl-android` 库本身是 GPL-3.0 且是第三方依赖——**只借鉴架构，
  不引入**；NewPipeExtractor 依然严禁
- yt-dlp 内建合并需要真实可执行的 ffmpeg 文件，而工程的 ffmpeg-kit 是
  进程内 JNI → **两遍策略**：`yt-dlp -J` 探测格式，合流优先单文件下载，
  否则分流下载视频+音频再用 ffmpeg-kit（`-c copy`）合并

**已实现**：
- `YtDlpPreferences`：stable/nightly 双通道、已安装 tag、自动检查、
  仅 Wi-Fi 开关
- `YtDlpUpdater`：**独立更新通道**——GitHub releases API 取 tag →
  只选 `name` 恰好为 `"yt-dlp"` 的官方归档资产（glibc 二进制绝不能选）→
  OkHttp 流式下载 → SHA-256 校验（对照 API 的 digest）→ 原子替换 →
  失败保留旧版（回滚）；每日一次节流 + 手动触发
- `YtDlpEnvironment`：解释器路径解析、ProcessBuilder（环境变量照抄
  youtubedl-android 生产配置：LD_LIBRARY_PATH/PATH/PYTHONHOME/HOME/
  TMPDIR/SSL_CERT_FILE）、Wi-Fi 判断
- `YtDlpDownloader`：批量顺序下载、探测→计划选择→`[download] %` 进度解析→
  取消（destroy 进程）、分流合并
- UI：环境状态卡（解释器/归档/版本）、更新通道（通道切换/检查更新/
  移动数据二次确认）、批量下载队列（每行一个链接，逐条进度，完成后
  **经 FileProvider 导入到任务**进入流水线）
- 导航 `Routes.YTDLP`，设置页「素材与下载」分组入口

**未完成（诚实说明）**：Python 解释器二进制尚未内置——交叉编译
CPython 3.12 + OpenSSL 是独立大任务，且沙箱 x86_64 无法冒烟测试 arm64
二进制（带病上线风险高于收益）。构建配方见 `yt-dlp集成调研.md` §6.2；
界面在缺失时明确提示，不静默失败。端到端下载待解释器就绪后真机验证。
